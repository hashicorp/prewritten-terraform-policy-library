# Ensure That IAM Users Are Not Assigned the Service Account User or Service Account Token Creator Roles at Project Level

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Identity and access management |

## Description

This control checks whether the `roles/iam.serviceAccountUser` or `roles/iam.serviceAccountTokenCreator` roles are granted to a `user:` principal at the project level via `google_project_iam_binding`, `google_project_iam_member`, or a `google_project_iam_policy` (whose `policy_data` is decoded and checked directly, since it is the authoritative resource that replaces the entire project IAM policy and is not interchangeable with the binding/member resources).

Both roles allow a principal to impersonate service accounts and, by extension, any resources or APIs those service accounts can access. Granting either role at the project level extends that impersonation ability to every service account in the project rather than a specific one, which violates least privilege and makes it far harder to audit who can act as which identity. These roles should instead be granted directly on the specific `google_service_account` resource the user legitimately needs to impersonate.

This rule is covered by the [1-7-project-iam](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/iam/1-7-project-iam.policy.hcl) policy.
