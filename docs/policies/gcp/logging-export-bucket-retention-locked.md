# Ensure That Retention Policies on Cloud Storage Buckets Used for Exporting Logs Are Configured Using Bucket Lock

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Logging and monitoring |

## Description

This control checks Cloud Storage buckets used as destinations by project, folder, organization, or billing-account logging sinks declared in the Terraform plan. Each matching bucket must have a non-zero retention period and `retention_policy.is_locked = true`. Buckets not used by a logging sink, and sinks with non-Cloud-Storage destinations, are outside this check.

The policy cannot correlate sinks or buckets managed outside the plan, nor resolve unknown sink destinations at plan time. It requires the destination bucket to be present as a `google_storage_bucket` resource in the plan to evaluate its retention settings.

This policy requires Google provider `>= 7.0.0, < 8.0.0`. Version 7.0.0 changed `retention_policy.retention_period` from a number to a string. The policy and its fixtures use that schema; Google 6.x is not supported by this policy. See the [Google 7.0.0 upgrade guide](https://registry.terraform.io/providers/hashicorp/google/latest/docs/guides/version_7_upgrade).

This rule is covered by the [logging-export-bucket-retention-locked](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/logging/logging-export-bucket-retention-locked.policy.hcl) policy.
