# Ensure That Service Account Has No Admin Privileges

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Identity and access management |

## Description

This control checks whether any service account has been granted the `Owner` or `Editor` basic role, or any predefined/custom role whose name contains "Admin" or "admin", at the project level via `google_project_iam_binding`, `google_project_iam_member`, or a `google_project_iam_policy` (whose `policy_data` is decoded and checked directly, since it is the authoritative resource that replaces the entire project IAM policy and is not interchangeable with the binding/member resources).

Service accounts are typically used by applications and workloads rather than individual users, so granting them broad administrative privileges significantly increases the blast radius of a compromised credential, since service account keys are often embedded in code, CI/CD pipelines, or long-running processes. Following the principle of least privilege, service accounts should be granted only the specific permissions required for their function rather than broad admin-equivalent roles.

This rule is covered by the [1-6-sa-no-admin](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/iam/1-6-sa-no-admin.policy.hcl) policy.
