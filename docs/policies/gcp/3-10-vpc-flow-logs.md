# Ensure that VPC Flow Logs is Enabled for Every Subnet in a VPC Network

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Network security |

## Description

This control checks that every `google_compute_subnetwork` (except those with a `purpose` of `REGIONAL_MANAGED_PROXY` or `GLOBAL_MANAGED_PROXY`, which are reserved for load balancer proxy infrastructure and don't carry regular workload traffic) defines a `log_config` block with `aggregation_interval` set to `INTERVAL_5_SEC`, `flow_sampling` set to `1`, `metadata` set to `INCLUDE_ALL_METADATA`, and `filter_expr` either omitted or explicitly set to `"true"`. Setting `filter_expr` to `"false"` (its only other practical value in most configurations) suppresses the export of every flow log record while leaving all other flow-log settings compliant, so it is checked explicitly.

VPC Flow Logs record network flow information (source/destination IPs, ports, protocol, byte/packet counts) for traffic to and from VM instances in a subnet. Without flow logs enabled, there is no record of network traffic patterns to support incident investigation, intrusion detection, or forensic analysis after a suspected compromise. The specific settings required here maximize log fidelity: a 5 second aggregation interval and 100% (`1`) sampling rate ensure flows aren't missed or aggregated too coarsely, and `INCLUDE_ALL_METADATA` ensures logs carry enough context (e.g. instance name, VPC) to be useful during an investigation.

This rule is covered by the [3-10-vpc-flow-logs](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/network/3-10-vpc-flow-logs.policy.hcl) policy.
