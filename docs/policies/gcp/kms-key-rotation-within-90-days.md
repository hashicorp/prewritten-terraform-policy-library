# Ensure KMS Encryption Keys Are Rotated Within a Period of 90 Days

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Identity and access management |

## Description

This control checks whether each Terraform `google_kms_crypto_key` sets a `rotation_period` of 90 days or less. Durations expressed in seconds (`s`), minutes (`m`), hours (`h`), or days (`d`) are supported. The configured period must use an integer value; unset, null, empty, malformed, fractional, or greater-than-90-day periods are treated as non-compliant.

The CIS requirement also checks that `nextRotationTime` is within 90 days of the current date. This policy cannot evaluate that criterion because `next_rotation_time` is not available in the policy's Terraform plan attributes. The source's default-value statement says keys rotate every 90 days, but this policy treats an unset `rotation_period` as non-compliant because the audit instructions require a rotation period to be configured.

This rule is covered by the [kms-key-rotation-within-90-days](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/iam/kms-key-rotation-within-90-days.policy.hcl) policy.
