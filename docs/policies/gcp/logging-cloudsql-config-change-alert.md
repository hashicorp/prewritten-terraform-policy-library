# Ensure That the Log Metric Filter and Alerts Exist for SQL Instance Configuration Changes

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Logging and monitoring |

## Description

This control checks for a `google_logging_metric` whose filter is `protoPayload.methodName="cloudsql.instances.update"` and an enabled `google_monitoring_alert_policy` whose `condition_threshold.filter` references that metric's `metric.type`. The alert must have at least one notification channel.

The Google provider defaults an omitted or null `enabled` value to true. Alerts referencing the metric only through a condition-absent condition do not satisfy the threshold requirement. Notification-channel suitability and alert thresholds are organization-specific and are not evaluated.

Metrics with an empty filter or a `cloudsql.instances.` operation are candidates for this control. Unrelated metrics and alerts, including unrelated disabled alerts, are outside its resource checks. A plan with no SQL-related metric cannot prove that the required metric exists, because there is no candidate resource to evaluate.

The `sql-config-alert-enforcement-level` input controls both resource policies and defaults to `advisory`.

This rule is covered by the [logging-cloudsql-config-change-alert](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/logging/logging-cloudsql-config-change-alert.policy.hcl) policy.
