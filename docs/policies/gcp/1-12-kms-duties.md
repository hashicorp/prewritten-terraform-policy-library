# Ensure That Separation of Duties Is Enforced While Assigning KMS Related Roles to Users

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Identity and access management |

## Description

This control checks that no single `user:` principal in the same project holds `roles/cloudkms.admin` together with any of `roles/cloudkms.cryptoKeyEncrypterDecrypter`, `roles/cloudkms.cryptoKeyEncrypter`, or `roles/cloudkms.cryptoKeyDecrypter`, across `google_project_iam_binding` and `google_project_iam_member` resources (including combinations of the two resource types), and across a `google_project_iam_policy`'s decoded `policy_data` (which can grant both roles within a single document, since it is the authoritative resource that replaces the entire project IAM policy).

Cloud KMS Admin can manage and rotate cryptographic keys, while the crypto roles allow encrypting or decrypting data with those keys. A user granted both the ability to administer keys and the ability to use them for encryption/decryption undermines separation of duties: they could rotate or delete a key to cover their tracks after using it, or grant themselves further access. Splitting key administration from key usage across different individuals reduces the risk of insider misuse or a single compromised account being able to both access and destroy evidence of encrypted data access.

This rule is covered by the [1-12-kms-duties](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/iam/1-12-kms-duties.policy.hcl) policy.
