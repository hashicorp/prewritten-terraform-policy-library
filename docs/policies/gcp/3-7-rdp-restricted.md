# Ensure That RDP Access Is Restricted From the Internet

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Network security |

## Description

This control checks that no enabled, ingress `google_compute_firewall` rule allows TCP or "all protocols" traffic on port 3389 from an unrestricted source range. A rule is only flagged when it is not `disabled`, its direction resolves to `INGRESS` (the provider default when `direction` is omitted), at least one of its `source_ranges` is an all-addresses range, and its `allow` blocks permit port 3389 either explicitly, via an empty (all-ports) `ports` list, or via a port range that includes 3389 — for a protocol of `tcp`, `all`, or the raw IP protocol number `6` (which the GCP API accepts as an equivalent alias for `tcp`).

`source_ranges` accepts IPv6 as well as IPv4, so both `0.0.0.0/0` and `::/0` are treated as unrestricted. Ranges are matched on a `/0` prefix length rather than on literal address text, which also covers non-canonical spellings such as `0::/0` and `0:0:0:0:0:0:0:0/0`. Note that a source range deliberately split into halves (for example `0.0.0.0/1` plus `128.0.0.0/1`) covers the whole internet but is not detected by this control.

RDP is a frequent target for internet-wide scanning and automated brute-force attacks, and has been the entry point for numerous high-profile ransomware incidents. Allowing RDP from any source address means any internet-connected attacker can attempt to authenticate against the instance. Restricting RDP to specific, trusted CIDR ranges (such as a corporate VPN or bastion host) removes this exposure for anyone outside those ranges.

This rule is covered by the [3-7-rdp-restricted](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/network/3-7-rdp-restricted.policy.hcl) policy.
