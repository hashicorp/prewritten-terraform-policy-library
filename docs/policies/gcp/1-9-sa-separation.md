# Ensure That Separation of Duties Is Enforced While Assigning Service Account Related Roles to Users

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Identity and access management |

## Description

This control checks that no single `user:` principal holds both `roles/iam.serviceAccountAdmin` and `roles/iam.serviceAccountUser` in the same project, across `google_project_iam_binding` and `google_project_iam_member` resources (including combinations of the two resource types).

`roles/iam.serviceAccountAdmin` allows creating, deleting, and managing service accounts, while `roles/iam.serviceAccountUser` allows impersonating them. A user holding both roles could create a new service account and then immediately impersonate it to perform actions that bypass their own access restrictions, effectively self-granting elevated privileges. Enforcing separation of duties between service account administration and service account usage closes this privilege-escalation path.

This rule is covered by the [1-9-sa-separation](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/iam/1-9-sa-separation.policy.hcl) policy.
