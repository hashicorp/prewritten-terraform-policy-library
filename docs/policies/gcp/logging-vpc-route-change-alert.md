# Ensure That the Log Metric Filter and Alerts Exist for VPC Network Route Changes

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Logging and monitoring |

## Description

This control checks for a `gce_route` log metric covering both `compute.routes.delete` and `compute.routes.insert` events, and an enabled alert policy whose `condition_threshold.filter` references that metric's exact `metric.type`. The two route methods must be an OR alternative; AND, negated, or one-method filters do not satisfy the requirement.

The policy checks threshold-condition filters only; an alert that references the metric only in a `condition_absent` or another condition type does not qualify. The Google provider defaults an omitted `enabled` value to true; an explicitly disabled policy does not qualify. Notification-channel suitability and alert thresholds are organization-specific and are not evaluated.

A plan with no `google_logging_metric` resource cannot be evaluated because there is no metric resource to anchor the policy on. Filter syntax is checked textually against the prescribed form, not with a full Cloud Logging query parser.

This rule is covered by the [logging-vpc-route-change-alert](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/logging/logging-vpc-route-change-alert.policy.hcl) policy.
