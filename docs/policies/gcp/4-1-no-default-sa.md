# Ensure That Instances Are Not Configured To Use the Default Service Account

| Provider | Category |
| -------- | -------- |
| Google Cloud Platform | Compute security |

## Description

This control checks whether a `google_compute_instance` explicitly configures a custom `service_account.email`, and flags instances that omit the `service_account` block entirely, leave `email` empty or null, or set `email` to the project's default Compute Engine service account (`<project-number>-compute@developer.gserviceaccount.com`).

The default Compute Engine service account is automatically granted the broad `Editor` role on the project unless that behavior has been explicitly disabled, and it is shared across every instance that doesn't specify another account. If an instance using the default service account is compromised, the resulting credentials can be used to affect any resource the `Editor` role can reach across the whole project. Assigning each instance (or group of instances) a narrowly-scoped custom service account limits the blast radius of a compromised VM to only the permissions it actually needs.

This rule is covered by the [4-1-no-default-sa](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/gcp/compute/4-1-no-default-sa.policy.hcl) policy.
