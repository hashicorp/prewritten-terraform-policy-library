# S3 general purpose buckets should be encrypted at rest with AWS KMS keys

| Provider            | Category |
| ------------------- | -------- |
| Amazon Web Services | Encryption of data-at-rest |

## Description

This control checks whether Amazon S3 general purpose buckets are encrypted at rest using AWS KMS keys. The control fails if a bucket does not have a server-side encryption configuration that specifies a KMS-managed key (either `aws:kms` or `aws:kms:dsse`) with an explicit, non-default customer-managed KMS key ID. Buckets using only AES-256 (SSE-S3) or the default AWS-managed S3 key (`aws/s3`) are considered non-compliant.

Encrypting S3 data at rest with AWS KMS provides an additional layer of access control because AWS KMS keys are managed separately from the data and can be audited, rotated, and restricted using key policies and IAM policies. This helps meet regulatory and compliance requirements that mandate encryption of stored data and key management separation.

This rule is covered by the [s3-bucket-should-be-encrypted-at-rest](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/aws/s3/s3-bucket-should-be-encrypted-at-rest.policy.hcl) policy.
