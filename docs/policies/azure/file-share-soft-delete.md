# Ensure Soft Delete for Azure File Shares is Enabled

| Provider | Category |
| -------- | -------- |
| Azure    | Storage security |

## Description

This control checks whether Azure Storage Accounts have file share soft delete enabled with a retention period between 1 and 365 days. File share soft delete preserves deleted file shares and their contents for a configurable retention period, allowing recovery from accidental or malicious deletion.

Without soft delete, deleted Azure file shares are permanently removed and cannot be recovered. Enabling this feature provides an important data recovery mechanism for shared file storage. `share_properties` is only valid for `Standard`-tier `Storage` (GPv1) or `StorageV2` accounts, or `Premium`-tier `FileStorage` accounts — replication type has no bearing on support. Accounts outside those kind/tier combinations (such as `BlobStorage`, `BlockBlobStorage`, or a Premium-tier `StorageV2` premium-page-blob account) are excluded from enforcement since they have no file share service.

This rule is covered by the [file-share-soft-delete](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/azure/storage/file-share-soft-delete.policy.hcl) policy.
