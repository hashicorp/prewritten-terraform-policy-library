# Ensure that VPN Gateway Point-to-Site Authentication Uses Microsoft Entra ID Only

| Provider | Category |
| -------- | -------- |
| Azure    | Network security |

## Description

This control implements CIS Azure Foundations Benchmark v6.0.0 control 7.9.

This control checks whether Azure VPN gateways with point-to-site client configurations use Microsoft Entra ID authentication exclusively. Restricting authentication to an identity provider supports centralized access management rather than separate certificate or RADIUS credentials.

The policy requires `vpn_auth_types = ["AAD"]` and nonblank `aad_tenant`, `aad_audience`, and `aad_issuer` values. Root certificates and RADIUS servers must not be configured. Gateways without a point-to-site configuration and non-VPN gateways are outside scope.

**Enforcement note:** an absent or unresolved authentication-type list is deferred, while a known empty list fails. Unresolved Entra metadata is also deferred. A speculative plan with unknown values does not prove that the deployed gateway uses Entra-only authentication.

In schema-aware local tests, omitted nested Entra metadata is null, not a computed unknown, and fails the nonblank requirement. Null authentication-list elements do not exempt a configuration from the metadata checks.

Enforcement defaults to `advisory` and can be configured with the `vpn-gateway-entra-auth-only-enforcement-level` input.

This rule is covered by the [vpn-gateway-entra-auth-only](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/azure/network/vpn-gateway-entra-auth-only.policy.hcl) policy.
