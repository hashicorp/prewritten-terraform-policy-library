# Ensure 'Additional email addresses' is Configured with a Security Contact Email

| Provider | Category |
| -------- | -------- |
| Azure    | Monitoring |

## Description

This control implements CIS Azure Foundations Benchmark v6.0.0 control 8.1.13.

This control checks whether declared Microsoft Defender for Cloud security contacts contain one or more syntactically valid email addresses. Configured security contacts help route notifications to the appropriate security team.

Configure `email` on `azurerm_security_center_contact` from the HashiCorp AzureRM provider. Multiple addresses must be comma-separated; blank entries, malformed addresses, and trailing empty entries fail validation. All declared contacts are checked regardless of their `name`.

**Enforcement note:** this control checks address syntax, not mailbox ownership, deliverability, or whether notifications are enabled. It evaluates only contacts declared in the Terraform plan and cannot detect a missing contact. The AzureRM resource does not expose Owner-role selection, minimum alert severity, or attack-path risk thresholds; those controls are not implemented.

Enforcement defaults to `advisory` and can be configured with the `security-center-contact-email-configured-enforcement-level` input.

This rule is covered by the [security-center-contact-email-configured](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/azure/monitor/security-center-contact-email-configured.policy.hcl) policy.
