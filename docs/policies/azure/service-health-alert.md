# Service Health Activity Log Alert

| Provider | Category               |
| -------- | ---------------------- |
| Azure    | Logging and monitoring |

## Description

CIS Azure Foundations v6.0.0 control 6.1.2.11 evaluates declared ServiceHealth activity-log alerts. Matching alerts must be enabled, cover subscription scope, notify an action group, cover all services, and cover all five supported event types or leave events unrestricted. Additional narrowing criteria are rejected.

The supported event types are Incident, Maintenance, Informational, ActionRequired, and Security. Omitted, null, or empty service selections represent unrestricted services; literal `All` is not a substitute. Region selection is permitted because this control does not explicitly require every region. Unknown values defer where the policy cannot establish a violation.

**Coverage:** This resource-level policy follows the benchmark's portal audit, not its Incident-only remediation example. It cannot detect missing alerts or verify notification delivery.

Scopes must include a subscription; omitted, null, or empty scopes fail. Notification actions must include a nonblank action-group ID; omitted, null, or blank IDs fail.

Requires `hashicorp/azurerm >= 4.0.0, < 6.0.0`. Enforcement defaults to `advisory`, configurable through `service-health-alert-enforcement-level`.

This rule is covered by the [service-health-alert](../../../policies/azure/monitor/service-health-alert.policy.hcl) policy.
