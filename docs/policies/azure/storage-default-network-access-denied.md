# Ensure that Storage Account Default Network Access is Set to Deny

| Provider | Category |
| -------- | -------- |
| Azure    | Network security |

## Description

This control implements CIS Azure Foundations Benchmark v6.0.0 control 9.3.2.3.

This control checks whether Azure storage accounts deny network access by default when public network access is enabled. A deny-by-default rule limits connectivity to explicitly permitted network sources.

Configure inline `network_rules.default_action = "Deny"` or a matching `azurerm_storage_account_network_rules` resource with `default_action = "Deny"`. Exactly matched standalone rules take precedence over inline settings. If multiple standalone rules match, all must deny access. Accounts with `public_network_access_enabled = false` are exempt from the default-action requirement.

Standalone network-rule resources also require `Deny`, unless their exactly matched storage account has public network access disabled.

**Enforcement note:** correlation depends on storage account IDs, so speculative plans can produce unknown results before IDs are resolved. This check does not validate individual permitted IP ranges or subnet rules and does not require a private endpoint to exist.

Enforcement defaults to `advisory` and can be configured with the `storage-default-network-access-denied-enforcement-level` input.

This rule is covered by the [storage-default-network-access-denied](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/azure/storage/storage-default-network-access-denied.policy.hcl) policy.
