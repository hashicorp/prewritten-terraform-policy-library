# Ensure that Network Security Groups are Configured for Databricks Subnets

| Provider | Category |
| -------- | -------- |
| Azure    | Network security |

## Description

This control checks that both subnets used by an Azure Databricks workspace have a network security group (NSG) with at least one Deny rule. For each `azurerm_databricks_workspace`, it builds the public and private subnet IDs from `custom_parameters` and looks for an `azurerm_subnet_network_security_group_association` for each subnet. The associated `azurerm_network_security_group` must contain a rule with `access = "Deny"`, either inline in `security_rule` or as a standalone `azurerm_network_security_rule`.

NSGs on the Databricks subnets restrict which traffic can reach cluster nodes. A workspace without VNet injection, a subnet with no NSG association, or an NSG that only allows traffic does not meet the control. Subnet and NSG IDs are compared case-insensitively.

This rule is covered by the [databricks-subnet-nsg-configured](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/azure/databricks/databricks-subnet-nsg-configured.policy.hcl) policy.
