# Ensure That Multifactor Authentication Is Enabled for All Users

| Provider | Category |
| -------- | -------- |
| Azure    | Identity and access management |

## Description

This control evaluates `azuread_conditional_access_policy` resources that target `All` users and declare the `mfa` built-in control or an authentication strength policy. Matching policies must require the `mfa` control or one of the built-in MFA, Passwordless MFA, or Phishing-resistant MFA strengths. They must be enabled, cover all cloud applications and client application types, have no user exclusions or narrowing conditions, and prevent another grant control from bypassing MFA.

Custom authentication strengths alone do not meet this control. An OR grant must not offer an unverified strength, another built-in control, terms of use, or a custom authentication factor as an alternative to MFA.

The all-user, all-application check also requires `conditions.client_applications` and `conditions.applications.included_user_actions` to be omitted, null, or empty. Client-application selectors or filters and user-action selectors do not meet this control.

**Enforcement note:** This policy validates only declared Conditional Access resources that match its filter. It cannot detect a missing all-user MFA policy, and a plan with no matching resource does not establish tenant-wide MFA coverage.

**CIS audit note:** CIS 5.1.3 audits per-user MFA status. This implementation checks Conditional Access policy configuration instead; it does not read or validate each user's per-user MFA state (`Disabled`, `Enabled`, or `Enforced`). Enabling Conditional Access-based MFA does not change those per-user states, so a passing policy result is not evidence that the per-user CIS audit has passed. See [Microsoft's guidance on per-user MFA states](https://learn.microsoft.com/en-us/entra/identity/authentication/howto-mfa-userstates).

**Deployment note:** This control evaluates Conditional Access-based MFA. Security defaults must be disabled when replacing them with Conditional Access policies; they are alternative deployment approaches and should not both be enabled in the same tenant. This library does not currently include a security-defaults policy. See [Microsoft's guidance on disabling security defaults](https://learn.microsoft.com/en-us/entra/fundamentals/security-defaults#disabling-security-defaults).

Requires `hashicorp/azuread >= 3.9.0, < 4.0.0`. Enforcement defaults to `advisory` and is configurable through `mfa-enabled-all-users-enforcement-level`.

This rule is covered by the [mfa-enabled-all-users](../../../policies/azure/iam/mfa-enabled-all-users.policy.hcl) policy.
