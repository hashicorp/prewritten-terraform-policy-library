# Ensure Private Endpoints are used to access Azure Databricks workspaces

| Provider | Category |
| -------- | -------- |
| Azure    | Network security |

## Description

This control checks that every Azure Databricks workspace in the Terraform plan is accessed through a Private Endpoint. It evaluates `azurerm_databricks_workspace` resources and requires an `azurerm_private_endpoint` with a non-blank `subnet_id` and a `private_service_connection` whose `private_connection_resource_id` matches the workspace ID (case-insensitive) and whose `subresource_names` include `databricks_ui_api` or `browser_authentication`.

The workspace must also meet the Private Link prerequisites: the Premium SKU, VNet injection with both subnet names, and Secure Cluster Connectivity (`no_public_ip` not set to `false`). A Private Endpoint for another resource, or one using a different subresource, does not satisfy the check.

The Terraform plan does not include the connection's approval state, so this policy cannot confirm that Azure reports the connection as Approved.

This rule is covered by the [databricks-private-endpoints-used](https://github.com/hashicorp/prewritten-terraform-policy-library/blob/main/policies/azure/databricks/databricks-private-endpoints-used.policy.hcl) policy.
